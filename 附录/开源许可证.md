# 开源许可证选择指南

给开源项目选许可证是第一个重要决定。本文帮你快速理解主流许可证的差异，做出正确选择。

> 全平台通用。本文不做法律建议，选许可证请咨询律师。

---

## 什么是 Copyleft？

**Copyleft**（著佐权）是开源许可证的一种策略：允许修改和分发代码，但要求修改后的代码也必须以相同许可证开源。核心目的是防止有人把开源代码改一改就闭源商用。

- **强 Copyleft**：修改后的整个项目都必须开源（GPL、AGPL）
- **弱 Copyleft**：只要求修改过的文件开源，不要求整个项目（LGPL、MPL）
- **非 Copyleft**（宽松许可证）：允许闭源商用，不要求开源（MIT、Apache、BSD）

---

## 主流许可证对比

| 许可证 | 商用 | 修改 | 分发 | 再授权 | 专利授权 | Copyleft | 说明 |
|--------|:----:|:----:|:----:|:------:|:--------:|:--------:|------|
| MIT | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | 最简单，无限制 |
| Apache 2.0 | ✅ | ✅ | ✅ | ✅ | ✅ | ❌ | 宽松 + 专利保护 |
| GPLv3 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ 强 | 修改必须开源 |
| AGPLv3 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ 强（含网络） | 远程调用也算分发 |
| LGPLv3 | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ 弱 | 库专用，调用方可不开源 |
| BSD 3-Clause | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | 类似 MIT，多一条禁止背书 |
| MPL 2.0 | ✅ | ✅ | ✅ | ✅ | ❌ | ✅ 文件级 | 改文件必须开源 |
| Unlicense | ✅ | ✅ | ✅ | ✅ | ❌ | ❌ | 放弃所有权利，公有领域 |

> ✅ = 允许 / 支持 | ❌ = 不允许 / 不支持

## 简单决策流

```text
你希望别人使用你的代码吗？
├─ 完全无所谓 → MIT（最省事）
├─ 希望保留专利保护 → Apache 2.0
├─ 希望别人改了也必须开源
│  ├─ 普通软件 → GPLv3
│  └─ 网络服务 → AGPLv3（通过网页调用也算「分发」）
└─ 你写的是库
   ├─ 允许闭源调用 → MIT 或 LGPL
   └─ 要求调用者也开源 → GPL
```

### 一句话总结

| 场景 | 推荐许可证 |
|------|-----------|
| 个人小项目，不关心别人怎么用 | MIT |
| 公司项目，涉及专利 | Apache 2.0 |
| 想让别人改了的代码也必须开源 | GPLv3 |
| 做 SaaS / 网络服务，防止被人白嫖后闭源 | AGPLv3 |
| 写库，想让别人可以直接引用 | LGPL 或 MIT |
| 想把代码献给公有领域 | Unlicense 或 CC0-1.0 |

## ⚠️ 许可证兼容性（哪些不能混用）

| 你的项目许可证 | 可以包含哪些许可证的代码 |
|----------------|------------------------|
| MIT | MIT、Apache 2.0、BSD、Unlicense |
| Apache 2.0 | Apache 2.0、MIT、BSD、Unlicense |
| GPLv3 | **仅 GPLv3 兼容的许可证**（不兼容 Apache 2.0、MIT 等宽松许可证） |
| AGPLv3 | **仅 AGPLv3 兼容的代码** |
| LGPLv3 | GPLv3、LGPLv3、MIT、Apache 2.0 |

**核心规则**：
- **GPL 项目不能包含 MIT/Apache 代码** —— 宽松许可证允许闭源，这与 GPL 的 Copyleft 冲突
- **MIT/Apache 项目可以包含 MIT 代码，但不能包含 GPL 代码** —— GPL 要求整个项目也变成 GPL
- **AGPL 是最严格的** —— 它和其他所有许可证的兼容性都有限

> 如果你不确定，**只用你自己的代码，或者只用一个许可证的代码**，避免兼容性问题。

## 如何添加许可证

在项目根目录创建 `LICENSE` 文件，粘贴许可证全文。或者使用工具：

- **https://choosealicense.com** — GitHub 官方推荐，选完即生成
- **https://opensource.org/licenses** — 所有 OSI 认证许可证列表

GitHub 新建仓库时也可直接选择。

## 常见误区

| 误区 | 正解 |
|------|------|
| 没选许可证 = 默认开源 | ❌ 没许可证 = 保留全部版权，别人不能使用 |
| 用了 MIT 代码，我的项目也必须 MIT | ❌ MIT 允许闭源使用，不必开源 |
| GPL 代码完全不能商用 | ❌ GPL 允许商用，但要求修改后开源 |
| AGPL 只适用于网络服务 | ✅ 对，这是它和 GPL 的主要区别 |
| 改一行 BSD 代码也必须开源 | ❌ BSD 是宽松许可证，不要求开源 |

> 💡 **选择建议**：不确定时选 MIT。以后随时可以改成更严格的许可证（但不能改宽松的，因为已有的贡献者的授权你无法收回）。
